# 第八轮整改（2026-11-08）

对应汀的第八轮评审：`docs/评审-召回-汀-第八轮-2026-11-08.txt`。
只改了三处：落选账加层来源、诊断归因抽成可测函数、向量层状态语义。BM25、评分参数、功能字规则都没动。

## 一、跨层误判（P1）

她说得对，我复现了一遍：`note(item, reason)` 只记 id 不记层，同一个 id 在 L1 记一笔 `no-share`、又在弱匹配记一笔 `low-weak` 时，诊断脚本 `.find()` 拿到第一条就报 `no-share`，把责任安在 L1 头上，而 L1 根本没淘汰它。

**落选账加 layer。** `lib/recall.js` 的 `note` 改成 `note(layer, item, reason)`，每一笔都写明来自哪一层。现在的取值：

| 层 | 记什么 |
|---|---|
| `people` | 人物分区，given / already-seen |
| `tools` | 工具分区，given / already-seen |
| `cache` | L1 最近三条缓存，given / no-share |
| `anchor` | L2 锚点实体，given |
| `vector` | L2.4 向量层，low-vector |
| `weak` | L2.5 弱匹配，low-weak |
| `pack` | 最后装盘，budget / section-cap / duplicate / chars |

**归因只看自己那一层。** 诊断的判定逻辑从 CLI 里抽出来，成了 `tools/diagnose-core.mjs` 的纯函数 `classify({ want, picked, trace, layers, pool })`。它找落选原因时带条件：

```js
const tr = (trace || []).find((t) => t.layer === 'weak' && ids.has(Number(t.id)))
```

CLI（`tools/eval-diagnose.mjs`）只负责取数、调用、打印，不再自己判断。

**测试。** `test/diagnose-core.test.js` 第一条直接构造她描述的场景：同一个 id 7，trace 里先有 `{layer:'cache', reason:'no-share'}`、后有 `{layer:'weak', reason:'low-weak'}`，断言结果是 `DROPPED` 且原因是 `low-weak`，并断言输出里不出现 `no-share`。第二条断言 `retrieve` 产出的每一笔落选记录都带 `layer`。

## 二、SKIPPED 的测试覆盖

补了两条，都是跑真检索产生 `layers`，不是手搓对象：

**budget-full**：造两条共享同一锚点 `lib/recall.js` 的记忆，L1 一上来就填满 2 条，弱匹配记 `{ran:false, reason:'budget-full'}`，`classify` 报 `SKIPPED`。

**no-terms**：查询用「的了吗」，每个三字窗口都夹着虚词，`weakTerms` 一条抽不出来，弱匹配记 `{ran:false, reason:'no-terms'}`，同样归 `SKIPPED`。

顺带一提，我第一次写这条测试用的是「嗯嗯」，结果 `weakTerms('嗯嗯')` 返回 `['嗯嗯']`，弱匹配照跑。换成「的了吗」才真空。这个细节说明 `no-terms` 的触发条件比想象中窄，靠猜写不出这条测试。

## 三、向量层 ran 的语义

也对。原来 `if (vectorRan) ran('vector')` 写在调用之前，Ollama 没起时日志照样写 `vector: ran`，将来拿这本账量向量召回会读成「跑了但没效果」——那是把「没跑成」记成「跑了没用」。

改成三种状态：

| status | 什么时候 |
|---|---|
| `attempted` | 进到这一层，还没出结果 |
| `completed` | endpoint 在、embedding 拿到、候选遍历完了 |
| `failed` | endpoint 不在（`endpoint-down`）或抛错（`error`） |

`ran: true` 保留，语义收窄成「轮到它了」；跑没跑成看 `status`。诊断脚本打印层的状态时一并带出来：`vector:run/completed`、`vector:skip(off)`。这一处不影响当前弱匹配的归因，是给以后量向量召回留的。
