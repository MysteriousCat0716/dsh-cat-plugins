## 背景：为什么做这件事

插件原来默认依赖本机 Ollama 算向量（`qwen3-embedding:0.6b`）做语义召回。用户的实际处境是：Ollama 不能常开，占内存，他大多数时候根本没启动。也就是说这套设计在真实使用中一直是降级状态——向量层每轮探一次端口、失败、冷却 60 秒，然后退回词面匹配。

目标不是「把向量做得更好」，是**把依赖拿掉，让纯 SQLite 这条路更强**。

约束：插件要保持零 npm 依赖、零插件依赖（只碰宿主 5 个 API）。

## 改了什么，为什么

### 1. `53edd58` 向量层默认关

- `lib/embed.js` 新增 `vectorsEnabled()`，只有 `process.env.DSH_MEMORY_CORE_VECTOR === 'on'` 才真。
- `lib/recall.js:415` 的 `vector` 默认值改用它（原来是 `!== 'off'`）。
- `lib/index.js` 的后台 `embedPending` 加同一道闸。
- 新增 `test/vectors-off.test.js`：默认关时「只有向量相似的旧事不会被取回」。

理由：这层的收益上限是补一条候选（余弦 ≥0.55，最多 1 条），代价是常驻进程。代码自己的注释写着 `a vector never becomes the only reason to recall a memory`。

### 2. `416f122` 启动预热也受开关约束

`warmVector()` 原来在插件加载时无条件跑。关掉召回但启动时照样连一次 11434，那「不依赖 Ollama」就只说了半句。改成 `if (vectorsEnabled())` 才预热。

### 3. `094e649` 别名扩展

`lib/aliases.js`：维护若干组同义词（`考研: [上岸, 读研, 研究生, 备考, 专业课, 初试]` 等 6 组内置）。查询里出现组名或组内任一词，就把整组带进弱匹配的 `LIKE`。

设计选择：
- 扩展词按 **0.7 折算**：`weakScoreOf` 里 `hits += d`、`score += tf * weight * d`、`maxWeight = max(weight * d)`。
- 用户可放 `~/.dsh/memory/aliases.json` 覆盖同名组，路径可用 `DSH_MEMORY_CORE_ALIASES` 指定。
- 文件坏了静默退回内置，不抛。

理由：词面层最容易漏的是同一个东西的两种叫法，而这正好是向量层唯一能补的那点。把语义做成数据，不花模型。

### 4. `094e649` `recall_trace.picked_detail`

原来 `detail` 只记落选（`note()`），入选的 `section` 不落库，导致「向量层/弱匹配各救过几次」量不出来。新增列存入选条目的 `{id, source, section, score}`，老库走 `ensureColumn` 补列。

### 5. `094e649` `tools/eval-recall.mjs`

拿 `recall_log` 里 `used=1` 的真实轮次回放：同一 sid 下时间最近、且不晚于该轮的用户消息作为 query，跑现在的 `retrieve()`，看当时「真用上过」的记忆还在不在。

本机当前跑出来的基线：

```
样本 114（跳过 6 条找不到原话的）
命中 12 → 10.5%
命中时的层分布：
  weak     14
  people   5
  tools    3
  other    2
```

## 我自己知道的问题（先说，别替我遮）

1. **评测的 ground truth 不可靠。** `used=1` 是之后某一轮回填的「用上了」，但样本里能直接看到语义无关的配对：query 是「mnemon 记忆插件的核心是什么」，正样本却是「岸姐记得用中文思考」「工作区少东西了」。所以 10.5% 这个数只能当**同一套数据上的回归基线**，不能当绝对正确率。
2. **turn 映射是猜的。** `recall_log.turn` 是宿主 pre-step 的进程内轮次，和 `turns.seq` 不是一个东西。脚本用「同 sid 下 `t` 最近且 `<=` 该轮落库时间」去找原话，可能取错轮。
3. **别名 0.7 折扣的副作用我没算清。** 当 `df >= 2` 时 `weight * 0.7 < 0.7`，意味着**别名命中永远拿不到 `rare` 豁免**，必须靠原词凑够两个窗口。对「考研→上岸」这种 2 字词为主的组，可能实际上扩展了却仍然不生效。
4. **FTS5 没做，是我主动跳过的。** 当前 1046 条记忆、`LIMIT 200` 的候选池很少真正截断，`LIKE` 全表扫在这个量级不是瓶颈。换索引的收益是未来规模 + BM25 排序质量，但在这个 ground truth 不可靠的前提下改检索，等于拿坏尺子量新衣服。先补账本和别名，等账本可信了再动。
5. **别名表的内容是我拍的。** 6 组内置同义词没有外部依据，`代理: [vps, 机场, 翻墙, 节点, clash, reality]` 这种可能过宽。
