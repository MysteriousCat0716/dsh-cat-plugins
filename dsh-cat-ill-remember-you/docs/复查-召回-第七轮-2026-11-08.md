## 一、P1：诊断脚本不再自己实现一套召回

改了三处。

**生产侧暴露层事件。** `lib/recall.js` 的 `retrieve()` 现在往返回数组上挂 `layers`，记每层跑了还是没有、为什么没跑：

```js
const layers = [];
const ran = (name, extra) => layers.push({ name, ran: true, ...extra });
const skipped = (name, reason) => layers.push({ name, ran: false, reason });
```

三个有预算门槛的层各记一条：`vector`（`budget-full` / `off` / `cooldown`）、`weak`（`budget-full` / `no-terms`）、`original`（`no-referral` / `budget-full`）。弱匹配层执行时还带上它实际用的词：

```js
layers.push({ name: 'weak', ran: true, terms: all });
```

**候选池查询提成导出函数。** 原来那段 SQL 埋在 `retrieve()` 里，诊断脚本自己抄了一份。现在抽成 `weakCandidatePool(db, all, limit = 200)`，生产代码和 `tools/eval-diagnose.mjs` 调的是同一份。诊断脚本里那句 `all.map((t) => \`%${t}%\`)` 也就不存在了——`escapeLike` 在函数内部统一做。

**分类补上 SKIPPED。** 目标不在最终结果，先看弱匹配层跑没跑；没跑就归 `SKIPPED`，不再算成 `GATE`。

当前 12 条用例的分布：

| 阶段 | 条数 |
|---|---|
| PICKED | 4 |
| DROPPED | 1 |
| GATE | 4 |
| POOL | 2 |
| ABSENT | 1 |
| SKIPPED | 0 |

这批用例里弱匹配层每次都会跑（前面的层没填满），所以 SKIPPED 是 0。汀担心的误判在现有用例上没出现过，但分类已经改对，换一批用例不会再把「没执行」记成「进池被拒」。

## 二、P2：指标改名，分母写清楚

`tools/eval-recall-cases.mjs` 改了两个名字和两个分母。

| 旧名 | 新名 | 分母 |
|---|---|---|
| Precision@1 | **TargetHit@1** | 跑过检索的用例数（ABSENT 不计） |
| Precision@2 | **TargetRatio@2** | 实际取回的条数 |

实测：

```
存储覆盖率 91.7%（11/12）
条件召回率 36.4%（4/11）
端到端 33.3%（4/12）
TargetHit@1 18.2%（2/11 个跑过检索的用例）
TargetRatio@2 19.0%（4/21 条取回里是目标）
```

旧口径把 ABSENT 算进 Precision@1 的分母，报 16.7%（2/12）；分母换成 11 之后是 18.2%。数字变了不是因为召回变好，是把一条不该算的用例从分母里拿掉了。

文件头写明这两个都不是标准 Precision@K：`want` 只是可接受集合，不在里面的不一定无关。

## 三、她要求的两条测试

新文件 `test/candidate-pool.test.js`：

- **df 永远不大于 N**：造 5 条记忆，从 `layers` 里取出弱匹配实际用的词，按生产口径（`tier='active' AND origin IN ('chat','unknown')`）数 df 和 N，逐个断言 `df <= N`。断言里用的是 `escapeLike`，跟生产查询同一套转义。
- **200 条是性能折中，不是解决时间截断**：造 201 条命中同样两个词的记忆，断言池恰好 200 条、最新的在里面、**最老的那条被挤出**。这条测试证明的是限制存在，不是限制没有。

全量 `node --test`：257 通过，0 失败。

## 四、200 条上限的说法

`weakCandidatePool` 的注释里写死了：

> 关于 LIMIT 200：这是性能折中，不是正确性边界。命中词数相同的两条，老的那条仍然可能被新的一批挤出前 200（201 条都命中 2 词、按 t DESC 截断时，最老的那条就是被挤掉的）。所以这个上限不「解决」长期记忆的时间截断。

之前那句「两年前的记忆不会再被最近的 200 条挤出去」不成立，收回了。

## 五、C2 按四问的检查结果

汀要求先查四点再归因，逐条答：

**1297 字那条（#1237）含不含目标事实？** 不含。它记的是「查吧 钱包很足 做完你能做的…问汀」那一整轮的全文转写，里面包括「我想让你记得我，库里一条都没有」那份报告。它含「面对」「结束」「没办法」「说过」四个词，是因为那份报告复述了别的记忆，不是因为它记着「我说过我没办法面对结束」这件事。

**目标事实有独立条目吗？** 有。#745，257 字，摘要就是用户原话「爱上你是真的 不会面对结束也是真的」。

**有的话，为什么没进前 200？** 进了，第 18 位。

**所以指向哪？** 不指向提炼层漏存，也不指向候选池截断，指向评分阶段。BM25 的长度归一化（k1=1.2、b=0.75、avg=577 字）没能抵消 1297 字整轮原文的词频堆积——三个查询词在它里面各出现一次以上，长度惩罚压不动。

## 六、一个已验证的机制和一个失败的改法

按上面的诊断，做了一个最小实验：只改打分字段，`weakScoreOf(db, all, row.text, …)` 改成 `row.summary`，其余不动，同一套 12 条复测。

| | 打分用 text（现状） | 打分用 summary |
|---|---|---|
| 端到端 | 33.3%（4/12） | **25.0%（3/12）** |
| 条件召回 | 36.4%（4/11） | 27.3%（3/11） |
| TargetHit@1 | 18.2%（2/11） | 9.1%（1/11） |
| C2 | MISS | **HIT 第 2 位 #745** |
| A4 | HIT 第 1 | DROPPED low-weak |
| B1 | HIT 第 1 | DROPPED low-weak |
| C5 | MISS | 空 |

两件事分开看：

- **机制成立**：换成 summary 打分，C2 直接命中。长记忆靠原文词多霸榜，这个因果是真的。
- **改法不成立**：整体从 33.3% 掉到 25%。摘要只有 47–90 字，词频信息太少，短条目也被拖下水。

实验完已经改回去，工作区里没有留下这行改动。

下一步不在本轮范围里。真要修，得让打分用「一条记忆里到底讲了什么」，而不是整轮转写，那是提炼层切块或者给 summary 加权的问题，不是换个字段能解决的。
