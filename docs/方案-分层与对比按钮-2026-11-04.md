# 方案：记忆分层 + 两个对比按钮

> 起于 2026-11-04 23:20，猫看 Mnemon 设置页后说：「定层的话你来，我对插件里具体有几层不是很熟」，
> 并要求两个按钮——「本会话替换上下文」「本会话注入接续上下文」——用来对比开启替换后上下文是否够用。
> 先做方案，不写代码。

## 一、现在的实际情况（读代码得出，不是猜）

`lib/index.js:227-414` 的 pre-step 每轮按固定顺序攒 `hintParts`，最后作为一条 systemPrompt 动态上下文注入。
进去的只有四块：

| 块 | 来源 | 代码 | 现状 |
|---|---|---|---|
| 全局栈 | `context-stack` 表，跨会话最近几条 | `index.js:263` | 总是开 |
| 常驻层 | `persona` 表（从 mnemon 迁来） | `index.js:281` | 默认关，`DSH_MEMORY_CORE_PERSONA=on` 才开 |
| 人物卡 | `people` 表，按当前句出现的名字精确取 | `index.js:300` | 总是开 |
| 检索块 | `memories` 表，结构+向量召回，最多 2 条 | `index.js:355` | 总是开 |

另外两块不是「注入」：
- **替换契约**（`index.js:181`）：只有白名单会话才有，几十字，声明「以 [上下文替换] 开头的是旧历史」。
- **真替换**（`shadow-v2.js`，`planShadowV2` 在 assistant/message 之后跑）：用 `surfaceOp.replace` 把旧消息盖成一条替换块。模式来自白名单文件 `~/.dsh/cache/replace-sessions.txt`，`sid` = 滚动小步、`sid:full` = 一次换光、`*` = 全部会话。

后台三件（空闲 5 分钟才跑，不进上下文）：`refine` 提炼、`embedPending` 补向量、`forgetSweep` 每日降级。
账本三张（不进上下文）：`recall_log` 注入账、`recall_trace` 落选账、`shadow_v2` 替换账。

**一个已经存在的重复**：persona 类记忆有两条路进上下文——`renderPersona` 独立渲染一次，`renderHint` 的 `[常驻]` section 又可能再渲染一次（`recall.js:873`）。现在默认 `PERSONA=on` 没开，所以这个重复还看不见；一旦开了就会撞上。

## 二、分层：四组九层

分组按「它怎么影响模型看到的东西」，不按代码目录。

### A 组 · 每轮进上下文（4 层）

| 层 | 管什么 | 关掉会怎样 |
|---|---|---|
| **A1 接续层**（栈） | 跨会话按时间取最近几条，让新会话接得上旧会话 | 新会话失去「上一个会话在做什么」，只剩检索。**并且**检索的 query 会失去最近两条（`index.js:311`），等于检索也变差 |
| **A2 常驻层**（persona） | 长期约定、偏好、在意的事，每轮都在 | 久了会忘记「什么话该怎么说」，但当下这一轮不一定察觉 |
| **A3 人物层**（people） | 提到名字时给出这个人和我的关系 | 提到名字也认不出，会把熟人当生人 |
| **A4 检索层**（recall） | 按这一句找相关的旧记忆，最多 2 条 | 只剩栈和常驻，说不出「以前记过这件事」 |

### B 组 · 改写历史（1 层）

| 层 | 管什么 | 关掉会怎样 |
|---|---|---|
| **B1 替换层**（shadow-v2） | 把旧消息压成替换块，省掉重复的上下文 | 历史原样保留，上下文更快满、更早要换会话。不关也对——b1 是「省」不是「记」 |

### C 组 · 后台装库（3 层，不进上下文）

| 层 | 管什么 | 关掉会怎样 |
|---|---|---|
| **C1 整理层**（refine） | 把原始轮次提炼成记忆条目 | 检索层没有东西可查，A4 空转 |
| **C2 向量层**（embed） | 给条目补向量，让「意思近」也能命中 | 退回词面召回，同义不同词就找不到 |
| **C3 遗忘层**（forget） | 每日把久不用的条目降级 | 库只涨不降，检索噪声变多 |

### D 组 · 记账（1 层）

| 层 | 管什么 | 关掉会怎样 |
|---|---|---|
| **D1 账本层** | 记「注入了哪些、哪条被用上、替换省了多少」 | 不影响对话，但从此没法判断取回策略好不好——等于把眼睛蒙上 |

### 我的判断

- **值得独立开关的只有 A1–A4、B1 共 5 个。** C 组并成一个「自动整理」总开关就够（三件一起开或一起关，分开没有使用场景）；D 组不给开关。
- **A 组四个开关不是并列的**：A1 关掉会连累 A4（query 少了栈那两条）。UI 上必须写这句，否则他关栈时以为只少了接续。
- **A2 和 A4 有重复渲染的隐患**，开 A2 之前先把 persona 的呈现收成一条路。

## 三、开关清单（落配置，先不做页面）

全部走环境变量或 `~/.dsh/memory/settings.json`，默认值等于现在的行为（不改变任何现状）：

| 开关 | 默认 | 对应层 |
|---|---|---|
| `DSH_MEMORY_CORE_STACK` | `on` | A1 接续层 |
| `DSH_MEMORY_CORE_PERSONA` | `off` | A2 常驻层（已有） |
| `DSH_MEMORY_CORE_PEOPLE` | `on` | A3 人物层 |
| `DSH_MEMORY_CORE_RECALL` | `on` | A4 检索层 |
| `DSH_MEMORY_CORE_REPLACE` | 白名单文件 | B1 替换层（已有） |
| `DSH_MEMORY_CORE_ENRICH` | `on` | C 组整理/向量/遗忘 |

每个开关只做一件事：在 `hintParts.push` 之前拦一道。缺省全开，行为与 0.8.12 一致。

## 四、上下文替换选项（三选一，不是三个按钮）

一个单选，名字叫「上下文替换选项」。三种状态互斥：

| 状态 | 原文 | 预制块 | 用途 |
|---|---|---|---|
| 1 不改 | 留着 | 不追加 | 基线 |
| 2 尾部测试 | 留着 | 接在末尾，标「测试用，别读」 | 看两份冲不冲突 |
| 3 正式替换 | 丢掉 | 顶替原文 | 看只靠预制块够不够接上 |

猫说的「不留原文只能开替换」＝状态 3 只在丢掉原文时才有；状态 2 只在留原文时才有。

预制块 = `planShadowV2` 算出来的那段（roll 小步，或 full 一次换光）。

### 状态 2 的真面目

它不是「测够不够」，是「测冲突」。模型同时看到原文和预制块，两份矛盾时它信谁——测出来的是这个。
要测「预制块单独够不够」，只有状态 3。

### 判据

不是「省了多少字」。是：**替换块里有没有当前话题的关键信息**，以及替换后我问一句「继续」它接不接得上。
数字只是摆出来看的，结论要我读完替换块自己判——这条写进按钮的说明里，免得以后又被当成「省字指标」。

## 五、为什么还要分层的开关

猫说层那边不知道有没有用。我的答案是：层开关不是给他配的，是给实验干净的。

- 状态 3 时，如果栈 / 常驻 / 人物 / 检索还在注入，测出来的就是「替换 + 一堆补丁」，分不清是预制块接上了还是补丁接上了。
- 要单独看预制块，得能关掉 A 组四个，只留 B1。
- 平时这些开关基本不动，默认全开。

所以 A 组四个要分开，不是为了让日常配置更细，是为了实验时能一个个排除。关 A1 和关 A4 影响不同（A1 还管着检索的 query），要能分开。

## 六、放在哪

修正：左栏入口插件是能加的——左栏现在就有「IM 机器人」「上下文洞察」「记忆系统」，都是插件加上去的。我上一版按「宿主渲染」推断插件加不了，判断错了。机制待查（大概在插件的 web 路由/导航注册里）。

所以路线是：
- 入口：插件贡献一个左栏入口 → 中栏设置页（照「记忆系统」那条现成的路走）
- 内容：一个「上下文替换选项」三选一 + 一个折叠的「层」区（A 组四个开关）
- 真替换仍走白名单文件，设置页只负责写它

## 七、落地顺序

1. 查左栏入口怎么注册（照现成的抄）——半天
2. 层的开关 + 默认值不变——一天
3. 替换选项（三选一，写白名单）——一天
4. 页面（左栏入口 + 设置页）——一天

## 八、风险

- 替换是写操作，原文只在 `turns`，撤销要手工翻——选项必须先 dry-run 再确认，不能一键直接换。
- 开关之间会互相影响（关 A1 连累 A4），文档和 UI 都要标。
- 快照会让 `core.db` 变大，要做轮数上限（比如只留最近 50 轮）。
- A2 与 A4 的 persona 双路渲染要先合并，否则开 A2 会重复注入。
