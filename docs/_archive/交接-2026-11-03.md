## 3. 注入通道：今天最难的一段，定稿在 `lib/index.js`

插件想把 carry / recall 的文本塞进上下文，不能走两条路：

- **`decision.messages`**：宿主 `dsh-agent-loop` 的 `step()` 会把 pre-step 返回的每条非 `runtime-context` 消息 append 成 `user/message`——持久化、显示成用户气泡。这就是「我的记忆块跑进猫的消息里」那个 bug。
- **`decision.assembly.contexts`**：pre-step 的 `decision` 里根本没有 assembly（宿主先 assemble，再把 assembly 合并进 decision 交给 handler；插件在 handler 里看不到）。

最终：

```js
ctx.inject(['systemPrompt'], (scope) => {
  scope.systemPrompt.context({
    name: 'memory-core',
    order: 1000,
    interpolate: false,
    text: (context) => {
      const agent = context?.agent;
      if (!agent) return '';
      return hintBySid.get(agent.id) ?? hintBySid.get(agent.session?.id) ?? '';
    },
  });
});
```

pre-step 只负责算文本、存进 `hintBySid`；宿主在 `refreshContext` 时求值 provider，把它合进 runtime-context 快照（`source.kind === 'runtime-context'`），不再冒充用户消息。

**Cordis 教训**：对没在 `inject` 名单里声明的服务，访问会抛 `cannot get property "..." without inject`；外层 try/catch 会把它吞成一行日志，看起来像「注册失败」——查注入问题先看 `inject` 名单。
