## 一、已确认的八处

### 1. 截断砍在结论上（最要命，仍在）

- seq 414 原文 242 字，替换块保留到「区别只在开局给了什么」之前；被砍掉的「接得上不等于接得对，接上了还得看被接到了什么局里」正是上一轮问题的答案。
- seq 399 同理：「只能等它真换一次，然后我回头提一件旧事，看提得起来提不起来」被砍。
- 规律：说话的人把结论放在后三分之一，而这套截断恰好留下开场、砍掉收尾。
- 后果：能「接上」，接不住「答对」。

### 2. 账本数字失真（部分）

- `chars_before=599`、`chars_after=420`，实际丢 179 字（约 30%），但 `lost_ratio=0`。
- 原因：`lost_ratio` 是 `assessReplacement`（`lib/shadow-v2.js:237-255`）按**关键 token 缺失比例**算的，不是字符差；关键 token 都在文本里时它就是 0，与「删了多少内容」无关。
- `kept=7` 而原文只有 4 条消息，含义仍不明。
- 后果：账本不能用来判断「值不值得换」。

### 3. 伪装成对话（已修，事件层仍受限）

- 头已改 `[上下文替换｜旧消息压缩，非用户发言]`，正文角色改「用户 / 助手」，不再用「我说 / 他说」。
- 但事件载体仍是 `user/message`——宿主只允许它带 `sourceEventSeqs`（`assistant/message` 会被拒，官方 compaction 也这么做），所以 UI 上仍占用户消息的位置。
- 内容层可区分了，位置层改不了。另见第 8 条。

### 4. 元信息缺失（仍在）

- 没有时间跨度、没有逐条 seq 列表（只给区间）、没写为什么折在这里。

### 5. 关键词是实体不是主题（仍在）

- 「岸、AGENTS.md」——检索得到，但不知道这段在谈什么。

### 6. 定长截断不看信息密度（仍在）

- 28 字的寒暄原样保留，242 字的结论只留 120 字。

### 7. 因果关系被压平（仍在）

- 4 条跨两个话题（插件试跑、隔壁创造模式），替换成一条直线，读不出「第 3 条是针对第 2 条说的」。

### 8. 替换块占「用户消息」的位置（宿主层限制）

- 事件类型层只允许 `user/message` 作为 replace 载体；`system/message` 要求 `source.kind='system-prompt'`，`developer/message` 会被 `withoutDeveloperMessages` 过滤。
- 所以 UI 上旧助手回复被替换后，显示在用户的位置。只能靠内容层的「非用户发言」标注区分。
