## 先挑错（你们要求的）

1. **「每条 turn 生成一条候选」——如果是真的，这是退步。** 0.4 的 `groupTurns` 是按块（user + 其后 assistants）提炼的，结论在 assistant 的最后一条里；按条生成会把一个决定拆成多条碎片，user 提问行还会单独成条。如果 0.7.8 真改成了按条，建议改回按块，并把「块完整」做成提炼的触发条件之一（见问题 1）。
2. **entities 正则硬编码**（`猫|岸|DeepSeek|dsh[\w-]*|Ollama|qwen…`）。名单外的实体全部漏抽 → 检索跟着漏。这不是风格问题，是召回上限被名单钉死了。至少补一条通用规则：文件名/路径进 anchors 已经有了，实体侧加「引号词、连续大写词、`X：` 冒号前定义的词」。
3. **confidence=explicit 只靠 JUDGE 词，会把任务性指令和长期约定同权。** 「别再忘了带钥匙」和「以后架构都用 X」都命中「别再」。后者才是 persona 候选。修法不必加分类器：把命中的词写进 why，人工审核 persona 建议清单时有据可查。

## 1. 触发点：双通道，不要单选

各失败模式你们列的选项我都同意，直接给结论：

- **事件驱动（表态即提炼）**：只对 `preference` / `decision` 开——这两类的显式句（JUDGE 词命中 **user 行**）单条可判、不需要等上下文，而且拖了会丢场景。失败模式是判错，靠批通道兜底（见下）。
- **空闲 timer（已有机制）**：管 fact 和其余一切。触发条件从「攒 40 条」改成「**块完整**（assistant 最后一条落库）+ 空闲」——1:1 会话空闲几分钟就是块边界，比按条数贴近真实节奏。失败模式（会话永不空闲）用「每日兜底扫」关掉。
- 明确反对的：**会话结束触发**（长会话天天续，没有可靠信号，永不触发）和**出栈触发**（节奏由容量决定与内容无关，且那时这块早该被取回过了）。
- 两条通道产出同块时要**去重：键 `(source_sid, source_seq)`**，即时通道先到、批通道跳过已炼的。

## 2. 输入：块 + 一次按需的旧记忆查询

- **常规输入 = 块**（user 行 + 其后 assistant 行，带 `user：/assistant：` 前缀——`blockText` 已经这么做，保持）。块就是窗口，不要再加前后文。
- **栈不要给提炼器。** 栈是注入语境不是提炼语境——把别的会话的话喂进来，炼出来的记忆归属就乱了。这是防污染的结构性边界之一。
- **相关旧记忆只在一种情况下查**：新候选的实体/kind 命中旧条时，查一次用于改写判断（问题 4）。不做常规输入，否则旧记忆会「复读」——旧的措辞一遍遍被重新炼成新条。

## 3. 输出结构：加两个字段，别加四个

- **加 `supersedes`**（被推翻的旧条 id）——问题 4 的地基，没有它改写表示不了。
- **加 `by`**（提炼规则/模型版本号）——让记忆像摘要一样**可回炉重算**。规则升级后扫 `by < 当前版本` 的行重跑，`scanned_at` 的重试模式直接搬。
- **不要加适用条件**（结构化字段没人维护，写进 text/why 就够）、**不要加有效期**（retention 三档 + tier 曲线就是有效期，再加一层是两套真相）。version 同理被 `by` 覆盖。
- confidence (explicit/reported/uncertain) 是好设计，保留；渲染时 uncertain 的可以降权而不是不取。

## 4. 合并与改写：只加不改，票数升格

- **旧判断被推翻：不改旧条。** 加新条，`supersedes` 指向旧条，旧条 tier → `superseded`（不参与检索、不删行）。三个理由：① 符合你们「只标不删」的宪法；② **「他改过看法」本身就是该记住的信息**——跨会话接上人有时需要「上次你以为 X」；③ 渲染时新条可带「（已更新，此前是 X）」，模型不会当成两条矛盾记忆——矛盾消解靠显式指向，不靠相似度。
- **同一话题反复说：不合写文本，升票数。** 规则合写两段话必然产出谁都没说过的句子。判据复用你们已有的：recall 去重用的 `summary.slice(0, 40)`（或实体+kind 相同且间隔短）命中 → `mentions+1`；explicit 票数 ≥3 → 写进 persona 建议清单。`entities` 表的 mentions 计数是这个模式的现成先例。

## 5. 防污染：三条结构规则，全部可测

你们踩的坑（助手措辞当原话）在结构上封死：

1. **subject 跟表态词走，不跟篇幅走。** 现在的弱点是：块里 user 行很短时，`digestOf` 摘要主要取自 assistant 文本，读起来像他说的。规则：`preference` / `decision` 两类的表态词必须命中 **user 行**，否则降级为 fact / subject='assistant'。机械可判，零提示词。
2. **每条记忆必须能追溯到单一来源行**：`source_sid + source_seq + role` 齐全，渲染时「他说/我说」由 role 决定。禁止合并改写把两条来源混进一行（问题 4 的「不合写」同时服务这条）。
3. **注入回流已关死，确认别再打开**：栈/提示走 runtime context 不入历史（0.5 改对了），`source.kind` 过滤 + `INJECT_RE` 兜底。任何新的注入通道上线前，先证明它产生的字符串进不了 `ingestEvent`。

验证：抽 20 条新产记忆人工验 subject，错 0 才算防住。

## 6. 分层：四问判据

上一轮给过的判据压缩版，按顺序问：

1. **写得出「当时」吗？** 写得出场景的 → memories；无场景、跨项目常真的 → persona 候选。
2. **会被什么触发？** 有锚点/实体、能被特定话题唤起 → memories；每轮都该在场 → persona。
3. **能从 turns 机械恢复吗？** 能（单次任务过程、改文件的细节）→ 只留原文，不占 memories。memories 存「结论 + 指针」，原文永远是底账。
4. **票数到了吗？** explicit 且 mentions ≥3 → 进 persona **建议清单，人工确认**（租金意识：4096 字是挤掉别人换来的）。

**验证判据（比规则版「更好」的可操作定义）：**

- **回放集**：从 turns 人工标 20–30 个「真该留的瞬间」（约定/偏好/推翻各占几个），新旧提炼器各跑一遍，比**留对率**和**污染率**。测试集放 `~/.dsh/` 不进仓库（你们的边界规则）。
- **账本对照**：两周后 recall_log 里新通道条目的取回率 vs 旧条目；forget_log 误降数；persona 建议的人工采纳率。

这个版本的判断是：**不需要生成模型也能把提炼层从「拼句子」升级成「有账可查的判断」**——supersedes/票数/来源追溯全是纯 SQL。生成模型接入时只换 `refine()` 内部（你们接口本来就留了），上面的结构一个不用动。
