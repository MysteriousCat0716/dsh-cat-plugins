## 二、判据：四个问题，按顺序问

### 1. 谁在表态？（确定 `subject`）

只看**原始消息的说话人**，不看正文篇幅、不看谁转述、不看谁最终执行。

| 情况 | subject |
| --- | --- |
| 用户说「我想 / 我要 / 喜欢 / 不要 / 就这样 / 同意」 | `user` |
| 助手做决定、助手的技术结论 | `assistant` |
| 用户要求做某事、助手执行 | `user`（要求是用户的表态） |
| 系统动作、手册记录（`origin=manual`） | 默认 `assistant`，正文含用户原话引号才改 `user` |

### 2. 表了什么态？（确定 `kind`）

有明确的「愿/不愿、做/不做、取舍」，才配 `preference` / `decision`。

| 不算表态 | 应归 |
| --- | --- |
| 转述新闻、转述别人的话 | `fact` |
| 问题清单、追问（哪怕以「用户：」开头） | `fact` 或 `judgment` |
| 技术结论（「状态类句子没有名词，该单独一层」） | `fact` |
| 一次性安排（「今晚 20:00 提醒我备份」） | 不进记忆，进定时任务 |

### 3. 明天还用得上吗？（`retention`）

只管这两天的事，用完就废——不建记忆。判据：如果这句话的有效期短于一周，写进交接或定时任务，不占记忆条。

### 4. 能落到别处吗？（归属）

能写进 `AGENTS.md`、项目文档、代码注释的规则，不重复进记忆。记忆只放「跨会话要想起、但仓库里没有合适位置」的东西。

## 四、根因

不是规则没写，是**判据挂错了对象**：现在跟的是「来源消息是谁说的」，需要的是「谁在这里表了态」。

- 1912 的问题：正文是一句技术判断，没有表态词，却因为来自用户消息被记成 `decision`。
- 1973 的问题：`origin=manual` 的记录被默认写成 `subject=user`。

## 五、修法（可执行，不改数据结构）

1. **`origin=manual` 默认 `subject=assistant`**；只有正文里出现用户原话引号（`「…」` / `用户：…`）才改 `user`。
2. **`kind=decision` 必须有表态词**：`要/不要/我想/我同意/就这样/不做/换成/改成` 命中其一，否则降 `fact`；问题清单降 `fact`。
3. **新闻/转述检测**：正文以「听说 / 转述 / 以下是 … 的回复 / 官方说」开头 → `fact`。
4. **一次性安排**：正文含明确「今晚/明天 HH:MM 提醒」→ 不建记忆，进定时任务。
5. **篇幅截断**：`text` 只保留用户那一句表态 + 一行助手结论，不整段抄录。
