# 工具原文按需取回：今晚查到的结构

> 2026-11-03 深夜，自由时间。为明天「工具结果也能压进替换块」这条路先摸清底。

## 会话日志里的工具事件

文件：`~/.dsh/sessions/<workspace>/<sid>/session.v4.jsonl.zstd`
示例 sid：`session-3809c618-93fd-4835-a764-0da31146f6cf`（9806 事件，其中工具事件 2445 条）

- `tool/call`：`data: { turn, step, callId, name, arguments }`
- `tool/result`：`data: { turn, step, message, meta }`，其中
  - `message.role = 'tool'`、`message.source = { kind: 'tool', callId }`
  - `message.content[0].text` 是输出文本（或引用指针）

## 关键发现

大结果已经被宿主换成了**引用指针**，不是原文。例：

```
[Stored reference: refId=ref://session-…/read_files/0514e0a8-…; producerTool=read_files;
 totalItems=82; totalBytes=195121; referenceRoot=\\?\C:\…\default-workspace.
 Page with ops_result; inspect before relying on it]
```

所以「按 seq 取回工具原文」实际是两步：

1. 读会话日志，按 `seq` 定位 `tool/result`，取 `content[0].text`；
2. 若它是 `ref://…` 指针，原文在宿主的引用存储里（`ops_result` 能取，插件能不能直接读还没查）。

## 明天的验证顺序

1. 找一个**小结果**的 `tool/result`，确认 `content[0].text` 是原文而不是指针；
2. 找引用存储的实际路径（`~/.dsh/storages/` 下找 refId 或 `read_files/0514e0a8`）；
3. 若插件能直接读，工具原文取回就是「读 zstd + 定位 seq + 解引用」；
4. 若不能读，就在压掉前把工具结果**摘要**写进替换块，原文只留会话日志（调用方按需再取，不保证可读）。

## 边界

- 替换载体只能是 `user/message`；`tool/result` 可被区间覆盖（`replacementRange` 不限节点类型）。
- 压掉后模型看不到工具过程，只看替换块里的摘要——这是设计要的，但摘要要写清「工具名 + 关键结论 + seq 指针」。
