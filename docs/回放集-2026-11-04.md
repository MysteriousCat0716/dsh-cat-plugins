## 三、量出来的数

- **摘要体裁错：25 / 25。** 每条都是「问：…｜答：…」，没有一条是一句判断。
- **主语错：4 / 25（16%）。** 625、71、19、874——助手说的话被记成主体。
- **kind 错：3 / 25（12%）。** 1026、265 该是情绪；304 是「喜欢一个视频」被当成长期偏好。
- **摘要丢重点：2 / 25。** 936 截在开头，862 和 451 只留了我的理解。

## 四、一个更麻烦的数

25 条里我判「三个月后还用得上」的只有 10 条（含 3 条算一半），15 条不该进记忆——但现有提炼器 25 条全留。这不是它错，它的设计就是「先全存、召回再筛」。真正的问题是：**那 10 条该留的，有 8 条摘要写歪了。**

## 五、结论

提炼层的瓶颈不在分类，在 **summary 的写法**：现在它复述「谁说了什么」，而 recall 时我要的是「谁决定了什么」。

下一刀改 `digestOf`：按 subject 抽结论句，不抽最长句。「问｜答」这种问答对只适合过程记录，不适合当记忆的正文。

## 六、改后复跑（2026-11-04 19:2x）

`digestOf` 改成「谁做的判断就取谁的话」：

- 主语是我 → 取我的句子；
- 主语是他 → 他的话含决定/偏好词，或整句够长（≥30 字）→ 直接取他的话；
- 只有他确实在提问（「缓存这块要怎么改？」）→ 才补一句我的结论。

剩下 3 条不是体例问题：198、19、874 是「我的过程/我的打算」被当成了记忆——那是 `kind` 和 `subject` 的判据没到位（fact 类不看表态词，我的自述就落成了事实）。下一个要动的是这里，不是摘要模板。

## 七、第三刀：转发只建指针（2026-11-04 19:3x）

判据：`classify` 的第一条是「是不是他转来别人的话」——开头 24 字内出现 `copilot / gpt / claude / glm / 嘎啦吗 / 朋友 / 网友 / 群友 / B站 / 哔哩 / 知乎`，并在同一行跟着 `说 / 回复 / 评价 / 发来 / 提到 / 看到`，且整条 ≥120 字。`kind = 'reference'`，`summary` 只写「他转来一段话（原文 N 字）：首行」，不拼问答对、不冒充判断。

25 条里命中 4 条：71（朋友的三条召回建议）、198（copilot 评审）、663（copilot 架构评价）、1148（B 站上别人的记忆系统研究）。这 4 条原先分别落在 decision / fact，现在统一为 `reference`，`subject = user`。

判断：71 是「留一半」的那条——现在它的摘要还在（首行是三条建议的第一条），全文仍在 `text`，召回时能看到原文；这条不算丢。198 / 663 / 1148 本来就不该被当成我们的决定，这一刀把它们从判断类里摘出来了。
